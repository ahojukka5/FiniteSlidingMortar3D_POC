# Coupled bulk/contact equilibrium and augmentation

The coupled layer assembles finite-strain `TET4` bulk mechanics and one or more
mortar contact interfaces into a single global displacement system. It reuses the
existing analytical bulk tangent, analytical moving-mortar tangent, essential
constraints, dead loads, CSR storage, and projected augmented-Lagrange state.

## Surface-to-volume mapping

`MortarContactInterface` maps every contact-surface node to one node of the bulk
mesh. The reference coordinates are checked against the bulk mesh before a solve.
The local contact ordering is always

```text
[slave node DOFs, master node DOFs].
```

The local residual and tangent are scattered through that ordering. Duplicate
global indices across the two sides are not silently removed, which leaves a path
toward self-contact while preserving additive assembly semantics.

## Combined sparse pattern

`Tet4Sparsity.from_mesh` accepts optional dense local DOF blocks. The symbolic CSR
pattern therefore contains both

- element couplings generated by each `TET4`; and
- cross-body couplings generated by each contact interface.

Element tangents and contact tangents are accumulated directly into precomputed
CSR value positions. The reduced free-free linear solve remains dense for the
current verification-sized models, exactly as in the bulk-only Newton driver.

## Fixed-multiplier inner equilibrium

For accepted multiplier states, the global residual is

```math
R(u;\lambda)
= R^{\mathrm{bulk}}(u)
+ \sum_I A_I^T R_I^{\mathrm{contact}}(u;\lambda_I)
- f^{\mathrm{ext}},
```

where `A_I` is the Boolean local-to-global map of interface `I`. The smooth-branch
tangent is

```math
K(u;\lambda)
= K^{\mathrm{bulk}}(u)
+ \sum_I A_I^T K_I^{\mathrm{contact}}(u;\lambda_I) A_I.
```

`solve_coupled_equilibrium` applies the same Armijo residual globalization as the
bulk-only solver. Inverted bulk trials and explicit clipping, pallet, or inverse-map
topology errors are rejected rather than regularized.

## Contact-event policies

Every contact evaluation records a discrete branch signature containing

- integrated facet pairs;
- supported mortar rows; and
- active projected-pressure rows.

The `restart` policy permits an Armijo-decreasing trial to cross one of these
branches, accepts the displacement, and recomputes the residual and analytical
tangent on the new branch before the next Newton step. The history records every
such restart. The stricter `reject` policy shortens the line-search step whenever
the branch changes.

These policies do not invent a derivative at a nonsmooth event. They define how
the nonlinear solver moves between neighboring smooth branches.

## Outer augmented-Lagrange loop

`solve_augmented_contact` alternates

1. a converged fixed-multiplier coupled equilibrium solve;
2. KKT evaluation on every contact interface; and
3. an accepted projected multiplier update.

The outer solve stops only when all interfaces satisfy their separate penetration,
complementarity, projection, and multiplier tolerances. It returns every inner
Newton result, the accepted multiplier states, and a machine-readable augmentation
history. If the maximum augmentation count is reached, the returned multipliers
still correspond to the last equilibrium solve; a projected but unequilibrated
state is never reported as accepted.

## Verification benchmark

`benchmarks/coupled_mortar_patch.py` uses two independently meshed cube-star
`TET4` blocks and a matching unit-square standard-mortar interface. For this driver
verification, the overlap, normal, and matching-facet `D=M` operators are frozen
at their exact values. This isolates

- global contact scatter;
- cross-body CSR couplings;
- fixed-multiplier Newton convergence;
- activation-event restarts; and
- outer KKT convergence.

The benchmark is not a substitute for a moving-overlap finite-sliding example.
That next benchmark will use `MortarContactInterface` with the full projection,
clipping, pallet, inverse-map, and analytical `D/M` derivative chain.

The committed outputs contain augmentation and Newton CSV histories, final nodal
pressure/gap data, JSON metrics, and SVG convergence and pressure plots.
